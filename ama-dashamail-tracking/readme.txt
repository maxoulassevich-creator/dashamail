== Description ==
Передаёт в DashaMail события WooCommerce, кастомной корзины Foneona и формы RELOD Auth
в полной структуре из раздела «Сайты → Отслеживаемые события» личного кабинета DashaMail.

Каждое событие содержит:
* блок `customer` — email, телефон, имя и фамилия покупателя;
* блок `product` / `lines` — идентификатор из YML-фида, цену, количество и название товара.

== Карта событий ==
Источник истины — раздел «Отслеживаемые события» в личном кабинете DashaMail,
он полнее «Руководства для разработчика».

| Событие в кабинете              | Идентификатор              | Что отправляет плагин                                    |
|---------------------------------|----------------------------|----------------------------------------------------------|
| Посмотрел продукт               | ViewProduct                | customer + product (id, name, price, url, picture, sku)  |
| Посмотрел категорию             | ViewCategory               | customer + category (categoryId, id, name)               |
| Добавил продукт в корзину       | AddProduct                 | cart.addProduct + customer, product, quantity, price     |
| Удалил товар из корзины         | RemoveProduct              | cart.removeProduct + customer, product                   |
| Изменил количество товара       | SetProductQuantity         | cart.setProductQuantity + customer, product, quantity    |
| Очистил корзину                 | ClearCart                  | cart.clear + customer                                    |
| Активирован промокод            | PromoActivated             | customer + promocode (name, discount, amount)            |
| Оформил заказ                   | OrderCreate                | customer (fname, lname, email, phone) + order            |
| Оплатил заказ                   | OrderPaid                  | то же                                                    |
| Заказ выполнен                  | OrderFinished              | то же                                                    |
| Клиент авторизовался            | Authorization              | команда identify с identificator                         |
| Клиент идентифицирован          | Identify                   | customer                                                 |
| Регистрация покупателя          | UserRegistration           | customer (name, email, mobilePhone)                      |
| Посетитель подписался           | UserSubscribe              | customer + pointOfContact                                |
| Ввёл email без подтверждения    | UserSubscriberNoConfirmBTN | customer + pointOfContact                                |

Блок `order` дополнительно содержит `deliveryType`, `deliveryAddress`, `deliveryTime`,
`paymentType` и массив `lines` (плюс копию в `items` для совместимости).

== Исправления структуры относительно 0.9.2 ==
Версия 0.9.2 отправляла данные, которые DashaMail не распознавал:

* `OrderCreated` → правильный идентификатор `OrderCreate`;
* `OrderClosed` → `OrderFinished` (в руководстве для разработчика указан `OrderDone`,
  идентификаторы настраиваются в админке плагина);
* ключ `items` в заказе → `lines`;
* команда `identity` → `identify`;
* операция `UserIdentifier` → `Authorization`;
* ключ `identifier` → `identificator`, вложенный `profile` → `provider`.

Из-за последних трёх пунктов идентификация не срабатывала вовсе, поэтому в журнале
DashaMail все посетители оставались анонимными UUID.

== Почему колонка «Данные» была пустой ==
Две независимые причины:

1. Короткие команды `cart.addProduct`, `cart.removeProduct`, `cart.setProductQuantity`
   и `cart.clear` поддерживают состояние корзины, но не переносят ни блок `customer`,
   ни название товара. Плагин теперь дублирует их полным событием `async` с той же
   операцией. Режим задаётся настройкой «События корзины».
2. Событие с пустым `productId` DashaMail показывает как шаблон-заглушку. Такие события
   больше не отправляются, а причина пропуска пишется в лог плагина строкой `skipped`.

== Как опознать неавторизованного посетителя ==
Трекер DashaMail сам выдаёт анонимному посетителю UUID устройства и накапливает на нём
историю. Как только UUID связывается с email, вся прошлая история подтягивается к профилю.
Плагин связывает их пятью способами:

1. Вход в личный кабинет или регистрация — email берётся из WordPress.
2. Ввод email на оформлении заказа — с учётом чекбокса маркетингового согласия.
3. Ввод email в любой другой форме сайта (подписка, обратная связь) — настройка
   «Email в любой форме» с настраиваемым CSS-селектором.
4. Переход по ссылке из письма DashaMail с email в параметре адреса. Добавьте в ссылки
   рассылки параметр вида `?dm_email={{email}}`; поддерживается и base64. Это самый
   надёжный способ узнать посетителя, который ещё ни разу не авторизовался.
5. Оформление гостевого заказа — email из заказа.

Опознанный email сохраняется в cookie и в сессии WooCommerce, поэтому серверные события
корзины и заказа тоже содержат блок `customer`. Параметр адреса подделывается кем угодно —
для собственной проверки подписи ссылки есть фильтр `ama_dm_allow_url_identity`.

Важно: пока включена настройка «Маркетинговое согласие», посетитель без явного согласия
остаётся анонимным, а блок `customer` в события не подставляется. Это самая частая причина
«пустых» событий.

== Installation ==
1. Загрузите ZIP через Плагины → Добавить плагин → Загрузить плагин.
2. Активируйте.
3. Откройте WooCommerce → DashaMail Tracking.
4. Для текущего фида оставьте режим «Как в текущем YML Amarèssence».
5. Сверьте «Идентификаторы событий заказа» с разделом DashaMail «Отслеживаемые события».
6. Введите идентификатор точки подписки DashaMail, если требуется событие UserSubscribe.
7. Включите «Лог событий», в DashaMail включите тестовый режим и проверьте события.

== Abandoned cart ==
В DashaMail сценарий строится как:
«Добавил продукт в корзину» И НЕ «Оформил заказ» в следующие X минут.
Товарные карточки в письме берутся из YML-фида по `productId`, поэтому значение должно
в точности совпадать с атрибутом `offer id` фида. Название товара из события на карточку
в письме не влияет — оно нужно для журнала и условий сценариев.

== Filters ==
* `ama_dm_product_identifier` — итоговый productId.
* `ama_dm_category_identifier` — итоговый идентификатор категории.
* `ama_dm_product_payload` — блок product целиком.
* `ama_dm_customer_payload` — блок customer целиком.
* `ama_dm_operation` — идентификатор любой операции.
* `ama_dm_order_status`, `ama_dm_delivery_type`, `ama_dm_payment_type` — поля заказа.
* `ama_dm_delivery_time_meta_keys` — где искать дату доставки.
* `ama_dm_brand_taxonomies` — таксономии бренда.
* `ama_dm_allow_url_identity` — разрешение опознать посетителя по параметру адреса.
* `ama_dm_identity_cookie_lifetime` — срок жизни cookie с личностью.

== Important limitation ==
Плагин использует официальный фронтенд-трекер DashaMail. События OrderPaid и OrderFinished,
возникшие без активного браузера покупателя, сохраняются и отправляются при следующем визите
зарегистрированного покупателя либо при возврате гостя на страницу заказа. Для гарантированной
немедленной доставки нужен backend-метод DashaMail — код, идентификатор и секретный ключ
берутся из вкладки «Бэкенд» в кабинете. По той же причине не реализовано событие
ProductComeBack («Товар появился в номенклатуре»): оно происходит без участия браузера.
